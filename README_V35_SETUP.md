# BTN Pool & Wallet Analyzer V35 — CRM Reports

## What is included

- `index.html`: V34 interface retained, with a third **CRM Reports** tab.
- `server.py`: V34 BaseScan endpoints retained, plus CRM matching, PDF generation, Telegram delivery, schedule settings, and report history.
- `Dockerfile` and `requirements.txt`: backend image definition.
- `.env.example`: names of the private environment variables required by the V35 backend.

## Important separation

Do not overwrite the current V34 deployment or its repository files. Publish this V35 copy separately. The V35 page intentionally keeps the existing V34 BaseScan API URL for the Wallet Analyzer while the new CRM Reports tab connects to the separate V35 backend URL entered in the page.

The current Cloudflare Worker is reused as-is:
`https://btn-pool-api.luisedt.workers.dev`

No change to The Graph or the Cloudflare Worker is required by this V35 code.

## V35 backend environment variables

Set these in the **new V35 backend service**, not in the existing V34 service:

- `PORT=8765`
- `DATA_DIR=/app/data`
- `POOL_WORKER_URL=https://btn-pool-api.luisedt.workers.dev`
- `GOOGLE_SHEET_ID=1ZQDrHVckyG4tKPNSurzTKr72qUukT8YThG57JOjgQ7M`
- `GOOGLE_SERVICE_ACCOUNT_JSON` = full JSON contents of a Google service-account key (keep private)
- `ADMIN_API_KEY` = a long random secret generated by the administrator
- `TELEGRAM_BOT_TOKEN` = current BotFather token (keep private)
- `TELEGRAM_CHAT_ID=-5153779943`

### Google Sheets permission

1. Create a Google Cloud service account and enable the Google Sheets API for its project.
2. Create a JSON key for that service account.
3. Share the `CRM Wallets BTN` spreadsheet with the service account's `client_email` as **Viewer**.
4. Paste the complete JSON key into `GOOGLE_SERVICE_ACCOUNT_JSON` in the new V35 backend's private environment variables. Do not put it in GitHub or in `index.html`.

The backend reads only the `CRM Wallets` tab and requests the Sheets read-only OAuth scope. It does not write to the spreadsheet.

### Persistent storage

Attach a persistent volume to `/app/data` in the new V35 backend. This stores the schedule settings, report history, and generated PDFs across restarts.

## Publish flow

1. Keep the existing V34 repository/deployment unchanged.
2. Publish this V35 frontend as a separate GitHub Pages site or a separate branch/site.
3. Create a separate EasyPanel backend service from this V35 folder/repository copy.
4. Add the environment variables above and attach `/app/data` as persistent storage.
5. After EasyPanel provides the new backend URL, open V35 → CRM Reports and enter that URL plus the `ADMIN_API_KEY`.
6. Test a short date range first. Confirm the PDF and Telegram delivery before enabling weekly/monthly schedules.

## Report behavior

- Weekly: previous 7 completed days, sent on the configured weekday/time.
- Monthly: previous completed calendar month, sent on the configured day/time.
- Custom: manually selected start/end dates; optional Telegram delivery.
- Report history is stored locally by the V35 backend.

## Security notes

- Never commit `.env`, service-account JSON, Bot Token, or `ADMIN_API_KEY` to GitHub.
- The CRM Reports API requires `Authorization: Bearer <ADMIN_API_KEY>`.
- The PDF download and schedule/history endpoints are also admin-key protected.
- Telegram and Google credentials belong only in the private V35 backend environment.
